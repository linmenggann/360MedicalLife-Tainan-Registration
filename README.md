### 部署 Apps Script

1. 開啟上述試算表 → 擴充功能 → Apps Script，刪除預設內容後貼上 `apps-script/Code.gs`。
2. 在編輯器上方選擇函式 `setupSheets` → 執行，授權後會自動建立四個分頁與表頭（重複執行不會清除資料）。
3. 部署 → 新增部署作業 → 類型「網頁應用程式」，執行身分「我」、誰可以存取「所有人」。
4. 複製「網頁應用程式網址」，填入 `index.html` 內的 `CONFIG.API_URL`，commit 並 push。
5. 之後若修改 Code.gs，需「管理部署作業 → 編輯 → 版本：新版本 → 部署」才會生效。

試算表選單「報名系統」另有「清除快取」與「立即更新公開統計」。

網頁每 60 秒自動更新各梯次報名狀態（頁面在背景時暫停）；送出報名時後端會再次檢查名額與重複報名。
每人限報名一個梯次：後端以總表比對「人事號」或「身分證號」，任一相同即拒絕，不論選擇哪個梯次。
如需更改梯次，請由承辦人員在總表與原梯次分頁刪除該列後重新報名。
`API_URL` 留空時為示範模式，名額計數僅存於瀏覽器的 localStorage。

試算表選單「報名系統」提供「初始化分頁與表頭」、「顯示各梯次名額統計」與「身分名稱更新為新名稱」等功能（重新整理試算表後出現）。

## 報名成功／行前資訊通知信

報名成功後，Apps Script 會在背景（約一分鐘內）寄一封「報名成功通知 & 行前資訊」到報名者的 E-mail，附上行程 PDF，
並在總表與該梯次分頁的「通知寄送時間」欄記錄時間。寄信與公開統計更新都不在報名請求內執行，
報名網頁按下送出後約 1–2 秒即回覆成功。
送出報名時，只有回應帶有 `registered: true` 標記才顯示成功；若回應不是報名結果（Google 把 POST 轉成 GET 的情況），
網頁會自動再送一次確認：寫入成功即顯示成功，若第一次其實已寫入會回「已報名同一梯次」也視為成功，兩次都無法確認才請報名者稍後再試或聯絡教學部。
機制：報名寫入後建立一次性時間觸發器執行 `processRegistrationQueue`，
該作業會補寄所有尚未通知的報名者（附件只下載一次）並更新公開統計。相關設定都在 `Code.gs` 開頭的「通知信」區塊：

| 常數 | 說明 |
|---|---|
| `NOTIFY_ON_REGISTER` | `true` 報名成功後立即寄送；`false` 只用手動補寄 |
| `MAIL_SENDER_NAME` / `MAIL_REPLY_TO` | 寄件人顯示名稱與回覆信箱（回覆會寄到 910632@chimei.org.tw） |
| `MAIL_FROM_ALIAS` | 若 Gmail 已在「設定 → 帳戶 → 以這個地址寄送郵件」加入院內信箱，填入後寄件人即顯示該信箱；否則以 Google 帳號寄出 |
| `PDF_DRIVE_FILE_ID` / `PDF_URL` | 附件來源：優先雲端硬碟檔案，留空則從 GitHub Pages 下載 `assets/itinerary.pdf` |
| `SESSION_LABELS`、`MEETING_TIME`、`MEETING_PLACE`、`SIGNATURE_LINES` | 信中的日期、集合資訊與簽名檔 |

試算表選單「報名系統」提供：
- **預覽通知信（寄給自己）**：用總表第一筆資料（沒有資料則用範例）寄一封到執行者自己的信箱，確認版面與附件。
- **補寄尚未通知的報名者**：對「通知寄送時間」為空的報名者寄信並標記時間，已寄過的不會重複。

第一次執行會要求 Gmail 與雲端硬碟授權。Gmail 每日寄信額度（一般帳號 100 封／日）足以涵蓋三梯次名額。
若要停止自動寄信，把 `NOTIFY_ON_REGISTER` 改為 `false` 並重新部署。

### 長官及工作人員的行前資訊

長官及工作人員不走報名網頁，名單放在**另一份** Google 試算表（含「第一梯次」「第二梯次」「第三梯次」分頁，
欄位與報名總表相同，至少要有「姓名」「E-mail」）。名單含個資，不放進 GitHub（`.gitignore` 已排除 `*.xlsx`）。

1. 把名單 Excel 上傳到 Google 雲端硬碟 → 開啟 →「檔案 → 儲存為 Google 試算表」，複製網址。
2. 報名試算表選單「報名系統 → 預覽長官及工作人員通知信（寄給自己）」：第一次會要求貼上名單網址，之後會記住。
3. 「報名系統 → 寄送長官及工作人員行前資訊」：確認視窗列出所有收件人，按「是」後逐一寄出（附行程 PDF）。

寄送時間記在名單試算表的「通知寄送時間」欄（沒有這欄會自動補上），再次執行只會寄給尚未寄過的人。
若貼成報名試算表的網址會被拒絕，避免名單混入報名資料。

#### 匯入報名資料（計入各梯次總人數）

2026-10-08 起，長官及工作人員也加入報名試算表、計入各梯次總人數上限。請用選單「報名系統 → 匯入長官及工作人員至報名資料」，不要手動貼上：

- 讀取名單試算表的「第一梯次」「第二梯次」「第三梯次」分頁，加入報名試算表的「活動報名資料」與對應梯次分頁；名單的「活動報名資料」分頁只用來核對，不重複匯入。
- 身分保留「長官」「工作人員」（只接受這兩種，其他身分會略過並列出）；統計時合併為「長官/工作人員」。報名網頁的身分選單不會出現這個身分。
- **不會寄送報名成功／行前資訊 E-mail**：「通知寄送時間」填入匯入時間、備註寫「長官/工作人員匯入（報名成功及行前資訊已另行寄送）」。手動貼上的列因為沒有通知寄送時間，下一次有人報名時，背景作業就會寄信給他們，所以請用選單匯入。
- 人事號等文字欄依〈人事號欄位通用規則〉以純文字寫入；報名時間留空（儀表板顯示「—」、排在名單最後）。
- 同梯次已有相同人事號或身分證號的人會略過，可以重複執行；執行前會列出要匯入的名單請你確認。
- 長官及工作人員不會出現在公開的「問卷查詢」名單，也不能填寫活動滿意度調查；他們的人事號或身分證號已在報名資料中，若再從報名網頁報名會被視為重複報名。

## 人事號正規化與文字欄防轉換

依本機共用規格（`~/.claude/CLAUDE.md`〈人事號欄位通用規則〉）實作。

### 正規化

人事號與身分證號在前端送出前、後端寫入前都經過同一個 `normalizeId`（`index.html` 與 `Code.gs` 各一份，內容相同）：
全形轉半形、移除零寬字元、去前後空白、去開頭撇號（含 iPhone 的彎撇號 ‘ ’）、轉大寫。
`8607e7`、「 8607E7 」、「８６０７Ｅ７」、「‘8607E7」、「 '8607E7」一律存成 `8607E7`。
離開欄位時畫面也會即時換成正規化後的值。比對（重複報名、管理者加報查詢、寄信標記）兩邊都先正規化。
手機簡碼/分機、出生日期只去撇號與空白，不轉大寫。

「每人限報名一個梯次」是本專案的明確業務需求，與正規化無關；正規化只負責讓值一致。

### 試算表儲存

人事號、手機簡碼/分機、出生日期、身分證號四欄一律以文字寫入 Google 試算表。所有寫入都經過 `appendRow_`：

1. **先把該列這四欄的儲存格設為純文字格式（`@`），再寫入正規化值**。純文字格式下試算表不做任何型別判讀，
   `8607E7` 不會變成 8.607×10¹⁰、`0912345678` 不會掉開頭的 0、`1985-03-04` 不會被轉成日期。
2. **不可加前置撇號**。Apps Script 以 `setValues` 寫入時，撇號會被當成字面字元存進儲存格（顯示 `'B509A9`）。
3. 列號由 `getLastRow() + 1` 決定，整段寫入都在 `LockService` 鎖定內。

**修復既有資料**：選單「報名系統 → 清除人事號等欄位的前置撇號」會把四欄整欄設為純文字，再以正規化值重寫
（撇號在值裡或是儲存格文字標記都能清掉，小寫人事號也會轉成大寫）。已經被試算表轉成數字的儲存格
（例如 `86070000000`）**不會自動推算還原**，會列在完成訊息中，請對照人事資料人工修正。可重複執行。

**診斷**：選單「報名系統 → 診斷文字欄內容」列出前 3 筆的值、顯示值、編輯列內容與格式。

**驗收測試**：選單「報名系統 → 驗收測試：人事號不被轉成科學記號」。在暫存分頁以正式寫入流程寫入
`8607E7`、`B41242`，以及 `8607e7`、「 8607E7 」、「８６０７Ｅ７」、「‘8607E7」、「 '8607E7」，
檢查儲存值為字串、儲存值與顯示值都等於正規化值、格式為 `@`、編輯列不出現撇號，最後刪除暫存分頁。

### 匯出 Excel（.xlsx，主要格式）

儀表板「匯出名單 Excel」直接產生 .xlsx，每個儲存格都以文字型別（`inlineStr`）寫入。
Excel 直接開啟即為文字，人事號沒有撇號、不會變成科學記號。程式自行組出最小的 xlsx，不依賴外部函式庫。

### 匯出 CSV（資料交換用）

「匯出名單 CSV」是 UTF-8 含 BOM 的純值 CSV，不使用 `="…"`、前置撇號或 Tab 等方式規避，
其他系統或程式讀到的就是原值。用 Excel 開啟時請走「資料 > 從文字/CSV」，並把「人事號」欄設為「文字」。
直接雙擊開啟 CSV 時，Excel 仍可能把 `8607E7` 顯示成 `8.61E+10`；要直接開啟請改用 .xlsx。

**驗收測試**：開啟 `dashboard.html?csvtest=1`，頁首會多出「下載 CSV 驗收檔」與「下載 Excel 驗收檔」。
.xlsx 直接開啟、CSV 以「從文字/CSV」匯入並將人事號欄設為文字後，人事號欄都應為 `8607E7` 與 `B41242`（文字）。
（2026-09-24 以 Excel 16 實測通過；CSV 直接雙擊開啟時 `8607E7` 會變成 `8.61E+10`，屬規格接受的情況。）

## 管理者加報梯次（同一人報名多個梯次）

報名網頁限制每人只能報名一個梯次。需要例外讓同一人參加多個梯次時，由承辦人員在試算表執行：

1. 選單「報名系統 → 管理者加報梯次（同一人多梯次）」。
2. 輸入已報名者的人事號（不分大小寫）。
3. 輸入要加報的梯次，可多選，例如「第二梯次,第三梯次」或「2,3」。
4. 確認對話框會顯示姓名、身分、加報梯次與收件地址，按「是」執行。

系統以該同仁總表中的報名資料為基礎，複製到指定梯次的總表與梯次分頁，「備註」欄標示「管理者加報（原報名：…）」。
仍會檢查各梯次該身分的名額，已報名的梯次或額滿的梯次會略過並列出原因。
完成後每個加報梯次各寄一封報名成功／行前資訊通知信（附行程 PDF），並更新公開統計與儀表板。

### 載入速度與備援機制

後端讀取不重設試算表格式。名額與儀表板結果在 Apps Script 端快取 360 秒（`CACHE_SECONDS`）：
報名寫入後立即以最新資料更新快取（不必再讀一次試算表），每 5 分鐘的排程（`publishStats`）也會重建快取，
所以網頁與儀表板的讀取幾乎都直接命中快取。只有「直接在試算表手動修改資料」時最多延遲 6 分鐘才反映，
可用選單「報名系統 → 清除快取」立即更新。

實測（2026-09-24）：快取命中約 1.1～1.5 秒、未命中約 2.2～3 秒、冷啟動約 7.6 秒；Google 端偶爾會有 8～15 秒甚至更久的延遲，
也曾把 POST 請求轉成 GET 才執行（回來的是名額資料而不是預期的結果）。這些屬 Google 服務本身的狀況，無法從程式端消除，
因此儀表板與報名網頁都設計成不受影響：

儀表板載入順序：

1. 先顯示瀏覽器保存的上次資料（狀態列顯示「更新中…」），再背景更新。
2. 第一次開啟、沒有保存資料時，同時讀取公開統計試算表（約 0.4 秒）先畫出名額與圖表，名單等 Apps Script 回來再補上。
3. 以 **GET**（`?action=dashboard&key=…`）向 Apps Script 讀取名單，逾時 25 秒（`CONFIG.FETCH_TIMEOUT_MS`）。
   改用 GET 是為了避開「POST 被轉成 GET」；舊版後端不支援時會自動改用 POST 再讀一次。
4. Apps Script 沒回應或回應沒有名單時，**不顯示任何提示**：安靜地改用公開統計試算表（GViz，失敗再用發布的 CSV）更新人數與圖表，
   已載入的名單保留（名單標題會註明「名單更新於 hh:mm」），並在 15 秒後自動重試。
5. 全部失敗才顯示「無法連線」並保留上次資料。

報名網頁的名額區塊與身分選單採用相同策略：
- 開頁立即顯示上次保存的名額，同時讀取公開統計試算表先顯示，Apps Script 回來後換成即時名額；Apps Script 逾時 25 秒。
- 名額區塊下方只顯示「名額更新於 hh:mm」。Apps Script 沒回應時不顯示任何提示，安靜地改用較新的公開統計，並在 15 秒後自動重試；
  只有所有來源都連不上且完全沒有名額資料時，才顯示「暫時無法取得名額資料」。
- 完全沒有資料時，名額卡片與身分選單顯示「名額載入中」，不會顯示滿額的預設數字；仍可填表，送出時後端會即時檢查名額。
- 每位訪客每 60 秒更新一次，頁面在背景時暫停，減少 Apps Script 的執行次數。

#### 設定統計試算表備援（選配）

公開統計試算表的「統計」分頁只有統計數字（各梯次身分人數、梯次上限、餐食、每日人數、單位人數）。

⚠️ 2026-10-07 起另有「問卷查詢」分頁（活動滿意度調查的人事號查詢名單），**含人事號、梯次、身分、單位、姓名、職稱與已填寫編號**（使用者同意公開），任何拿到連結的人都能讀取；E-mail、手機、出生日期、身分證號、餐食不會放入。請勿把此試算表連結轉貼到公開場合。

1. 在 Apps Script 編輯器選擇函式 `setupStatsPublishing` 執行（或試算表選單「報名系統 → 建立公開統計試算表」）。
   會自動建立試算表「360°醫學人生 報名統計與問卷查詢名單（知道連結即可檢視）」、設為「知道連結的任何人可檢視」（GViz 端點需要）、
   安裝每 5 分鐘更新的觸發器，並在執行紀錄印出試算表網址與 GViz 端點。
   若已建立過，重新執行只會補上共用設定與觸發器，不會重建。
2. GViz 不需再設定：儀表板每次成功連上 Apps Script 時會記住統計試算表 ID。
   若希望第一次開啟就能在 Apps Script 無回應時讀取，可把 ID 填到 `dashboard.html` 的 `CONFIG.STATS_SPREADSHEET_ID`。
3. CSV 備援（選配）：開啟該試算表 → 檔案 → 共用 → 發布到網路 → 選擇「統計」分頁、格式「逗號分隔值 (.csv)」→ 發布，
   把網址貼到 `dashboard.html` 的 `CONFIG.STATS_CSV_URL`。

成功報名時也會立即更新公開統計。改用公開統計時，儀表板保留上次載入的名單並註明名單時間，Apps Script 恢復後自動換回即時名單。
- 修改 Code.gs 後記得「管理部署作業 → 編輯 → 新版本 → 部署」，儀表板的名單功能才會生效。

### 試算表與雲端硬碟

- 分頁欄位：`編號`、填寫時間、梯次、身分、單位、姓名、人事號、職稱、Q1～Q10、其他建議或回饋、最感動的一段話、活動照、社群媒體截圖、送出代碼。已建立的分頁缺少新欄位時，後端會把它插在表頭中前一個欄位的右邊（例如「其他建議或回饋」插在 Q10 之後），既有資料一併右移。
- **編號**：各分頁各自從 1 開始，取該分頁現有最大編號 + 1（刪除某一列後也不會重複使用編號）。
- 照片存到各梯次的「活動照」與「社群媒體截圖」資料夾（ID 在 `Code.gs` 的 `SURVEY_FOLDERS`），檔名一律 **`編號-梯次-姓名.副檔名`**（例：`1-第一梯次-王小明.jpg`），不含其他資料。試算表的「活動照」「社群媒體截圖」欄顯示檔名並連結到該檔案。
- 照片**不壓縮、以原檔上傳、不限檔案大小**（JPG、PNG、HEIC、RAW 等），只受 Apps Script 擁有者的雲端硬碟空間限制。
- 送出代碼一律由網頁產生；同一份問卷的重送、續傳都沿用同一組代碼。

### 照片上傳：Google Drive API 可續傳上傳（Resumable Upload）＋分塊續傳

1. 網頁 GET `?action=surveyUploadUrl` → 後端以 Apps Script 擁有者的權杖向 Drive API 申請「可續傳的上傳網址」，暫時檔名為 `上傳中-送出代碼-活動照.副檔名`，直接放在該梯次的資料夾。申請時帶入網頁的 Origin（只允許 `https://linmenggann.github.io` 與本機測試），瀏覽器才能直接對這個網址上傳。**權杖不會傳到網頁**，網頁只拿到這一個檔案專用的上傳網址。後端也會先確認此人事號有報名此梯次、且尚未填寫過。
2. 網頁把原檔切成 **8 MB 分塊**，直接 `PUT` 到上傳網址（`Content-Range`），檔案由瀏覽器直接推送到 Google 雲端硬碟，不經過 Apps Script。
3. **續傳**：分塊失敗（網路中斷、手機切到背景等）時，網頁等待後向後端查詢雲端已收到多少位元組（`?action=surveyUploadStatus`），從中斷處繼續；網路恢復或頁面回到前景會立刻繼續。連續失敗約 2～3 分鐘才停止，此時再按一次「送出問卷」仍從中斷處繼續。
4. 上傳網址記在本機草稿：重新整理或關閉頁面後再開，作答會自動還原；重新選**同一張照片**（檔名、大小、修改時間相同）會顯示「上次已開始上傳」，送出時從中斷處續傳。上傳網址的有效期限為一週，失效時自動重新申請。
5. **備援**：瀏覽器直接上傳連續失敗、但後端仍連得上（例如網路或 CORS 限制）時，網頁改用 `POST action=surveyUploadChunk` 由後端代傳分塊（一樣是 8 MB 分塊、可續傳）。
6. 送出問卷時只傳檔案 ID；後端確認檔案確實是這份問卷（送出代碼）上傳到正確資料夾的暫存檔，才改名為 `編號-梯次-姓名.副檔名`，並把同一份問卷沒用到的暫存檔（例如上傳後又換照片）丟到垃圾桶。
7. 沒有完成送出的暫存檔（`上傳中-` 開頭）會留在資料夾裡，可用選單「清除未完成送出的暫存照片（超過 1 天）」清除。
- 人事號等文字欄依〈人事號欄位通用規則〉以純文字寫入（`writeRowAt_`，與報名共用）；最感動的一段話以 RichText 寫入，以「=」開頭也不會變成公式。
- **每人每梯次限填寫一次**：查詢人事號時若已填寫過，會顯示「您已填寫過本梯次問卷（編號 N）」並停用送出按鈕；後端寫入前（含鎖定內）也會再檢查，同一人用兩支手機同時送出也只會寫入一份。管理者加報而參加兩個梯次的人，兩個梯次的問卷各可填一次。需要修改內容時，由承辦人直接在試算表更正。
- 每次送出帶一組送出代碼：Google 把 POST 轉成 GET、網路中斷或系統忙碌時，網頁會先用代碼確認是否已寫入，沒有才重送，不會產生重複的資料列或檔案。

### 啟用步驟

1. Apps Script 編輯器左側「服務」→ ＋ → 選「Drive API」→ 新增（啟用 Drive API，可續傳上傳需要）。
2. 貼上最新的 `Code.gs` → 儲存 → 部署 → 管理部署作業 → 編輯 → 版本「新版本」→ 部署。若跳出授權視窗，請按允許。
3. 重新整理試算表，執行選單「報名系統 → 建立活動滿意度調查分頁＋檢查雲端硬碟資料夾」：會建立三個分頁、檢查六個資料夾能否存取，並實際以 Drive API 分塊上傳一個小測試檔（成功後自動丟到垃圾桶）。顯示 ✘ 時依訊息處理（資料夾需「編輯者」權限；Drive API 未啟用請做步驟 1）。
4. 用一筆真實報名的人事號，到各梯次問卷填一次測試（建議用手機、上傳一張 50 MB 以上的照片），確認資料列、編號與檔名後，刪除測試資料列與測試照片。
