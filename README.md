### 部署 Apps Script

1. 開啟上述試算表 → 擴充功能 → Apps Script，刪除預設內容後貼上 `apps-script/Code.gs`。
2. 在編輯器上方選擇函式 `setupSheets` → 執行，授權後會自動建立四個分頁與表頭（重複執行不會清除資料）。
3. 部署 → 新增部署作業 → 類型「網頁應用程式」，執行身分「我」、誰可以存取「所有人」。
4. 複製「網頁應用程式網址」，填入 `index.html` 內的 `CONFIG.API_URL`，commit 並 push。
5. 之後若修改 Code.gs，需「管理部署作業 → 編輯 → 版本：新版本 → 部署」才會生效。

試算表選單「報名系統」另有「清除快取」與「立即更新公開統計」。

網頁每 30 秒自動更新各梯次剩餘名額；送出報名時後端會再次檢查名額與重複報名。
每人限報名一個梯次：後端以總表比對「人事號」或「身分證號」，任一相同即拒絕，不論選擇哪個梯次。
如需更改梯次，請由承辦人員在總表與原梯次分頁刪除該列後重新報名。
`API_URL` 留空時為示範模式，名額計數僅存於瀏覽器的 localStorage。

試算表選單「報名系統」提供「初始化分頁與表頭」與「顯示各梯次名額統計」兩個功能（重新整理試算表後出現）。

## 報名現況儀表板（dashboard.html）

- 顯示：總報名人數與額滿率、各梯次各身分的報名進度、梯次 × 身分堆疊圖、名額一覽表、
  每日報名趨勢、單位分佈、餐食統計、可篩選／搜尋的報名名單，並可匯出 CSV。
  名單只包含報名時間、梯次、身分、單位、姓名、人事號、職稱、餐食，不含 E-mail、手機、出生日期與身分證號。
- 名單資料由 Apps Script 的 `action=dashboard` 提供。`Code.gs` 的 `DASHBOARD_KEY` 與 `dashboard.html` 的
  `CONFIG.DASHBOARD_KEY` 需填相同值（預設皆為 `chimei360`）；兩者皆留空則不檢查。
- 儀表板網址知道的人都能看到名單，請只提供給活動承辦人員。
- 每 60 秒自動更新，也可按「重新整理」。

### 載入速度與備援機制

後端讀取不再每次重設試算表格式，名額與儀表板結果在 Apps Script 端快取 20 秒（`CACHE_SECONDS`），
成功報名後立即清除快取。儀表板載入順序：

1. 先顯示瀏覽器保存的上次資料（狀態列顯示「更新中…」），再背景更新。
2. 向 Apps Script 讀取即時資料，逾時 12 秒（`CONFIG.FETCH_TIMEOUT_MS`）。
3. Apps Script 無回應時，改讀公開統計試算表的 **GViz 端點**（`/gviz/tq`，即時，不經發布快取）。
   先以 CSV 格式 fetch，若被 CORS 擋下則自動改用 JSONP。
4. GViz 也失敗時，改讀「發布到網路」的 **CSV**（Google 端約延遲數分鐘）。
5. 全部失敗則保留上次資料並顯示「無法連線」。

#### 設定統計試算表備援（選配）

公開統計試算表只有統計數字（各梯次身分人數、限額、餐食、每日人數、單位人數），不含姓名或任何個資。

1. 在 Apps Script 編輯器選擇函式 `setupStatsPublishing` 執行（或試算表選單「報名系統 → 建立公開統計試算表」）。
   會自動建立試算表「360°醫學人生 報名統計（公開，不含個資）」、設為「知道連結的任何人可檢視」（GViz 端點需要）、
   安裝每 5 分鐘更新的觸發器，並在執行紀錄印出試算表網址與 GViz 端點。
   若已建立過，重新執行只會補上共用設定與觸發器，不會重建。
2. GViz 不需再設定：儀表板每次成功連上 Apps Script 時會記住統計試算表 ID。
   若希望第一次開啟就能在 Apps Script 無回應時讀取，可把 ID 填到 `dashboard.html` 的 `CONFIG.STATS_SPREADSHEET_ID`。
3. CSV 備援（選配）：開啟該試算表 → 檔案 → 共用 → 發布到網路 → 選擇「統計」分頁、格式「逗號分隔值 (.csv)」→ 發布，
   把網址貼到 `dashboard.html` 的 `CONFIG.STATS_CSV_URL`。

成功報名時也會立即更新公開統計。備援模式下儀表板不顯示報名名單，Apps Script 恢復後會自動切回即時資料。
- 修改 Code.gs 後記得「管理部署作業 → 編輯 → 新版本 → 部署」，儀表板的名單功能才會生效。
